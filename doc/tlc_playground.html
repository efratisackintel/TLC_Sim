TLC's decision

Speed (MCS) iModulation & coding = data density. Picked from SNR & interference. Higher MCS = faster, but needs a cleaner signal.
–
Streams iSISO = 1 lane, MIMO = 2 lanes (≈2× speed). MIMO is chosen only when SNR is high enough.
–
Bandwidth iChannel width. Wider ≈ more speed, but power spreads thinner so it needs more SNR.
–
Guard Interval iSymbol spacing. 0.8µs = more throughput; 3.2µs = resists echo/delay-spread. TLC compares the two measured PER curves and keeps whichever gives the best SR×throughput. In this AWGN dataset both curves are ~identical, so it keeps 0.8µs for max speed — long GI wins mainly on multipath channels.

Success Ratio per MCS — what TLC actually watches iTLC never sees SNR. It measures the Success Ratio of each rate (acked ÷ sent) and keeps the highest MCS whose SR × throughput is best while SR stays healthy. Bars = SR per MCS derived from each rate's measured PER curve at the set SNR; the dashed lines are the real decision gates (95% / 90% / 15%). Blue = TLC's pick.

PER vs SNR — picked curve iEvery MCS's measured PER-vs-SNR curve for the picked bandwidth / streams / GI (SISO = 1×2, MIMO = 2×2). Colour = MCS (blue low → red high); the bold curve is TLC's pick. The dashed line is your current SNR; where it crosses each curve is that rate's PER. Below a curve's swept range PER saturates to 100%, above it to 0%.
